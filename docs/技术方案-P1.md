# 技术方案：TXT 阅读器 P1（功能扩展）

> 版本：v0.2（P1）　|　状态：草案　|　关联文档：《产品设计文档.md》《技术方案.md（MVP）》

## 1. 方案概述

本方案为「TXT 阅读器」P1 阶段的技术落地说明，与《产品设计文档.md》§4.2 对齐，在 MVP 基础上新增 5 项能力：

| 序号 | 功能 | 核心思路 |
|---|---|---|
| ① | 简易章节识别 | TXT 按「第 X 章」正则切分；EPUB 按 OPF 书脊（spine）天然切分 |
| ② | 书签 / 高亮划线 | 以「字符偏移」为唯一定位基准，标注独立存储，正文渲染时按区间切分 |
| ③ | 单本书内全文搜索 | `indexOf` 顺序扫描 + 大小写不敏感，返回偏移与上下文片段 |
| ④ | 阅读时长统计 | 阅读器打开期间定时累计，写入独立 stats 存储，避免改写整本正文 |
| ⑤ | EPUB 支持 | 解压 EPUB → 抽取纯文本 + 章节 → 复用 TXT 阅读管线 |

**延续 MVP 的架构原则**：核心复杂度继续收敛到框架无关的纯 TS 模块（`lib/` 下），组件层保持薄；EPUB 不另起一套阅读器，而是「解压 → 抽纯文本 → 复用现有分页/标注/搜索/进度」的收敛策略。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| EPUB 解压 | `fflate`（`unzipSync`） | 纯 JS、约 8KB、无原生依赖，浏览器与 Node 通用，可同步解压，便于单测 |
| EPUB 元数据/正文 | 正则抽取（非 `DOMParser`） | 规避浏览器 API 依赖，让解析逻辑在 Node 环境可直接单测；EPUB 的 OPF/container 结构规整，正则足够 |
| 标注/时长存储 | IndexedDB 独立 store（`bookmarks`/`highlights`/`stats`） | 避免每次标注/计时都重写整本正文（正文 MB 级，写入代价高） |
| 其余 | 沿用 MVP（React 18 + TS + Zustand + `idb` + Vitest + CSS Modules） | 不引入新框架，降低迁移成本 |

**明确不使用**：`jszip`（体积大、API 异步链长）、`jschardet`（P1 不涉编码）、`DOMParser` 依赖的 DOM 库（`jsdom`/`happy-dom`，仅为测试引入过重）、任何后端服务。

## 3. 总体架构

```
导入文件(ArrayBuffer)
   ├─ .txt ──► encoding.decodeText ──────────┐
   └─ .epub ─► epub.parseEpub（解压+OPF） ───┤  抽取 { content, chapters?, encoding }
                                             ▼
                                      Zustand store（内存态，唯一事实源）
                                             │  显式动作落盘
                                             ▼
                    IndexedDB：books / settings / bookmarks / highlights / stats
                                             │  启动 loadAll 读回
                    ┌────────────────────────┼──────────────────────┐
                    ▼                        ▼                      ▼
              书架视图（进度/时长）    阅读器（分页渲染）    标注/搜索/章节（纯函数）
```

- **定位基准统一为「字符偏移」**：书签 `offset`、高亮 `[start, end)`、章节 `start`、翻页 `lastPage` 均可互相换算（页 = `floor(offset / CHARS_PER_PAGE)`），TXT 与 EPUB 共用一套导航/标注逻辑。
- **EPUB 复用 TXT 管线**：`content` 仍为纯文本，`chapters` 为显式章节数组；阅读器内 `book.chapters ?? parseChapters(book.content)` 二选一。

## 5. 核心模块设计

### 5.1 章节识别（`lib/chapters.ts`）

TXT 无原生章节，按行首正则识别「第 X 章」等标题：

- 正则：`/^[ \t]*((?:第[0-9零一二三四五六七八九十百千万两]+[章卷节回部集篇]|序章|序言|楔子|前言|后记|尾声|番外)[^\r\n]*?)[ \t]*$/gm`（`m` 多行、行首匹配，兼容 `\r\n`）。
- 章节偏移指向标题行首字符位置，二分查找当前章节。

```
parseChapters(text: string): Chapter[]          // 顺序扫描，返回 [{ title, start }]
chapterIndexAt(chapters, offset): number       // 二分：最后一个 start <= offset 的下标，无则 -1
```

### 5.2 书签 / 高亮（`lib/annotations.ts` + `bookmarks`/`highlights` store）

定位基准为字符偏移，正文按页渲染时把高亮的**绝对区间映射到页内相对区间**再切分：

```
pageHighlightRanges(highlights, pageStart, pageLen): Array<[number, number]>
splitByHighlightRanges(text, ranges): TextSegment[]       // 合并重叠区间，产出 { text, highlighted }
bookmarkAtOffset(bookmarks, offset): Bookmark | undefined
```

- 书签按「当前页起始偏移」切换（同一偏移已有书签则删除）。
- 高亮在正文选区 `mouseup` 时用 `Range` + `toString().length` 计算页内偏移，映射回绝对偏移后落盘；渲染时高亮段包 `<mark>`，配色随主题（`--rhighlight`）。

### 5.3 全文搜索（`lib/search.ts`）

大小写不敏感的子串搜索，`indexOf` 顺序扫描 O(n)，可处理 MB 级文本；结果带上下文片段并折叠空白。

```
searchText(text, query, { limit = 200, context = 24 }): SearchResult[]
// SearchResult = { index: number; snippet: string }
```

搜索框输入 200ms 防抖，结果按「片段 + 页码」展示，点击跳到 `floor(index / CHARS_PER_PAGE)`。

### 5.4 阅读时长（`lib/duration.ts` + `stats` store）

阅读器打开期间每 15s 结算一次增量，关闭时结算剩余时长，写入 `stats`（独立 store，避免改写正文）：

```
formatDuration(seconds): string    // 不足1分钟 / X 分钟 / X 小时 Y 分钟
addReadingTime(bookId, seconds)    // 内存累加 + putStat 落盘
```

书架卡片展示 `累计阅读 {formatDuration(stats[bookId])}`。

### 5.5 EPUB 解析（`lib/epub.ts` + `fflate`）

```
parseEpub(bytes: Uint8Array): { title, author, content, chapters }
```

流程：`unzipSync` → 读 `META-INF/container.xml` 定位 OPF → 解析 OPF 元数据（`dc:title`/`dc:creator`）与 `manifest`/`spine` → 按书脊顺序逐个 XHTML 抽纯文本（块级换行、去标签、解码实体），每个 spine 项记为一条 `Chapter`。

辅助纯函数（均导出、可单测）：

```
normalizeZipPath(path): string        // 去前导 ./ 与 /
resolvePath(baseDir, href): string    // 相对 OPF 目录解析，去 query/hash、解码 URL 编码
xhtmlToText(html): string             // XHTML → 纯文本
```

> 取舍：P1 只抽纯文本，丢弃图片/CSS/排版；`content` 复用 TXT 的分页与全部标注/搜索能力。

## 6. 存储设计（IndexedDB `qingyue-db`，version 1 → 3）

升级策略：`upgrade` 内用 `objectStoreNames.contains(...)` 幂等建表，v1→v3 平滑新增。

| store | keyPath | 记录 | 说明 |
|---|---|---|---|
| `books` | `id` | Book | 新增 `chapters?`（EPUB 显式章节；TXT 为 undefined） |
| `settings` | `key` | `{ key:'reader', fontSize, lineHeight, theme }` | MVP 不变 |
| `bookmarks` | `id` | `{ id, bookId, offset, createdAt }` | P1 ② |
| `highlights` | `id` | `{ id, bookId, start, end, createdAt }` | P1 ② |
| `stats` | `bookId` | `{ bookId, seconds }` | P1 ④ |

- 删除书籍时级联删除该书的 `bookmarks`/`highlights`/`stats`。
- 进度（`books.lastPage`）仍为 300ms 防抖写；书签/高亮/时长直接写（记录小）。

## 7. 关键流程

**导入 EPUB**：`arrayBuffer → parseEpub → Book{ content, chapters, encoding:'utf-8' } → putBook → 书架排序`。

**章节导航**：`当前偏移 = currentPage × CHARS_PER_PAGE → chapterIndexAt 求当前章 → 上一章/下一章/目录跳转 = gotoPage(floor(start / CHARS_PER_PAGE))`。

**添加高亮**：`选区 → 页内偏移(start,end) → 绝对偏移(pageStart+start, pageStart+end) → addHighlight → 渲染时 splitByHighlightRanges 包 <mark>`。

**全文搜索**：`输入(防抖) → searchText → 结果列表 → 点击 gotoPage(floor(index / CHARS_PER_PAGE))`。

**时长累计**：`打开阅读器计时 → 15s 结算 → addReadingTime → 关闭结算剩余 → 书架展示`。

## 9. 风险与权衡

| 风险/权衡 | 影响 | 应对 |
|---|---|---|
| EPUB 只抽纯文本，丢图片/排版/样式 | 图文混排书体验弱 | P1 接受；后续升级「HTML 渲染 + 图片资源」 |
| 正则解析 OPF/XHTML，非严格 XML/实体全量 | 边缘 EPUB 可能解析不全或漏章节 | 覆盖常见 OPF2/3 结构；异常捕获后跳过该文件 |
| 固定字数分页页边界不准（MVP 遗留） | 大字号需页内滚动 | 后续可升级测量式分页或连续滚动 |
| 时长按「阅读器打开时长」计，非「真实阅读」 | 挂机会计时 | P1 接受；后续可加「可见/活跃」判定与节流 |
| 高亮偏移依赖选区映射 `toString().length` | 含 mark 分段时需精确 | 用 TreeWalker/`Range` 相对内容根计算，已覆盖 |
| IndexedDB v1→v3 升级 | 老数据兼容 | `upgrade` 幂等建表，旧 store 不删 |

## 10. 关键决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| EPUB 接入方式 | 抽纯文本复用 TXT 管线 | 避免重写分页/标注/搜索，成本最低 |
| EPUB 解压 | `fflate` | 纯 JS、轻量、Node/浏览器通用、可单测 |
| XML/HTML 解析 | 正则而非 `DOMParser` | 保持 `lib/epub.ts` 在 Node 可单测，无需引入 DOM 依赖 |
| 标注定位 | 字符偏移（非页码/DOM 节点） | 与分页/章节/搜索统一换算，结构简单 |
| 标注/时长存储 | 独立 store | 避免每次写标注都重写 MB 级正文 |
| 章节来源 | EPUB 显式 `chapters`，TXT 正则兜底 | `book.chapters ?? parseChapters(content)` 二选一 |
| EPUB 章节标题 | XHTML 的 `h1~h3` → `<title>` → 「第 N 节」兜底 | 多数 EPUB 的 `<title>` 为书名，`h1` 更贴近章名 |
