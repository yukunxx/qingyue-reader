# 技术方案：TXT 阅读器（MVP）

> 版本：v0.1（MVP 规划）　|　状态：草案　|　关联文档：《产品设计文档.md》

## 1. 方案概述

本方案为「TXT 阅读器」MVP 的技术落地说明，与《产品设计文档.md》对齐。核心结论：**纯前端 Web 应用，无后端、无 SSR**，用最简技术栈跑通「导入 → 阅读 → 记住进度」闭环。

工程上把复杂度收敛到两个框架无关的纯 TS 模块——**编码探测**与**固定字数分页**，其余（书架、设置、主题）均为薄 UI 层。现有 `demo/index.html` 作为交互参考，其 UI 骨架可直接迁移，但以下三处需替换：

1. 读文件方式：`readAsText`（默认 UTF-8，遇 GBK 乱码）→ `ArrayBuffer` + 编码探测；
2. 存储：`localStorage` → IndexedDB；
3. 分页：预生成 `pages` 数组（冗余占内存）→ 存原文、按需 `slice`。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite | 快、零配置、静态产物天然适合纯前端部署 |
| 框架 | React 18 + TypeScript | 生态最大，后续 EPUB/搜索等扩展可复用现成方案；TS 对编码/分页边界逻辑收益高 |
| 状态管理 | Zustand | 轻量、样板少；此规模无需 Redux |
| 样式 | CSS 变量（主题）+ CSS Modules（隔离） | 沿用 demo 的 `--rbg/--rfg` 变量思路，三种主题即三组变量 |
| 存储 | IndexedDB + `idb` | 可容纳 MB 级文本；`idb` 约 1KB、Promise 化，免去原生 API 样板 |
| 测试 | Vitest | 与 Vite 同源，配置少，适合纯逻辑单测 |
| 编码 | 原生 `TextDecoder` | 无需引入第三方探测库，确定性优于启发式探测 |
| 部署 | 任意静态托管 | GitHub Pages / Vercel / Nginx 均可，无构建期特殊要求 |

**明确不使用**：后端服务、数据库、SSR/SSG、PWA（MVP 阶段）、Redux、Tailwind（可选不必要）、`jschardet` 等启发式探测库。

## 3. 总体架构

```
导入文件(ArrayBuffer)
   │  编码探测 → 解码为 string
   ▼
Zustand store（内存态）
   │  显式 save 动作
   ▼
IndexedDB（books / settings）
   │  启动时 load 回内存
   ▼
书架视图  ⇄  阅读器视图
   │               │
   └── 固定字数分页（按需 slice）
```

- **内存态为唯一事实源**：组件只读写 store；IndexedDB 是"变更时快照"，仅在显式动作（导入/删除/翻页记录进度/改设置）时写入，避免高频无谓落盘。
- **渲染按需**：阅读器每页只渲染当前页文本（一个 `slice` 结果），整本文字始终驻留内存但不进 DOM。

## 4. 目录结构

```
src/
  main.tsx
  App.tsx
  types.ts                 # Book、ReaderSettings 等类型
  lib/
    encoding.ts            # 编码探测（纯函数，无 React 依赖）
    pagination.ts          # 固定字数分页（纯函数）

  store/

  components/

```

> `lib/` 下的 `encoding.ts`、`pagination.ts` 保持纯函数、零 React 依赖，便于直接单测。

## 5. 核心模块设计

### 5.1 编码探测（`lib/encoding.ts`）

目标：正确解析 UTF-8 / GBK（含 Windows 常见 UTF-16）。

流程：

1. 用 `file.arrayBuffer()` 读文件，拿到 `Uint8Array`；
2. 优先按 BOM 判断：
   - `EF BB BF` → UTF-8（剥离 BOM 后解码）
   - `FF FE` → UTF-16 LE
   - `FE FF` → UTF-16 BE
3. 无 BOM 时：`new TextDecoder('utf-8', { fatal: true }).decode(buffer)`；
   - 解码成功 → UTF-8；
   - 抛异常 → 回退 `new TextDecoder('gb18030').decode(buffer)`（GB18030 是 GBK 超集，覆盖简体中文）。

接口（示意）：

```
detectEncoding(bytes: Uint8Array): Encoding   // 'utf-8' | 'utf-16le' | 'utf-16be' | 'gb18030'
decodeText(bytes: Uint8Array): { text: string; encoding: Encoding }
```

**边界与取舍**：MVP 只保证 UTF-8 / GBK / UTF-16；Big5（繁体）不在范围内，后续需要再引入 `jschardet`。解码一次性完成（整本 string 常驻内存），几 MB 文本内存开销可接受。

### 5.2 固定字数分页（`lib/pagination.ts`）

采用文档选定的「最快方式」——按固定字符数切片：

- 每页字数 `CHARS_PER_PAGE`（默认 720，可配置常量）；
- 第 N 页 = `text.slice(N * CHARS_PER_PAGE, (N + 1) * CHARS_PER_PAGE)`；
- 总页数 = `Math.max(1, Math.ceil(text.length / CHARS_PER_PAGE))`；
- 进度 = 当前页下标 `lastPage`，翻页即 `slice`，O(1) 随机访问，**不预生成 `pages` 数组**。

接口（示意）：

```
totalPages(text: string): number
pageAt(text: string, page: number): string
```

**取舍（已确认）**：固定字数切页不感知中英文/标点宽度与容器换行，页边界与屏幕不完全对齐；字号调大时单页可能需页内滚动。这是换取实现简单、进度确定性的代价，MVP 接受。

### 5.3 存储（`lib/db.ts`，IndexedDB + `idb`）

数据库 `qingyue-db`，version 1，两个 object store：

**`books`（keyPath: `id`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一 id（时间戳 + 随机串） |
| title | string | 书名（取自文件名去扩展名） |
| author | string | 作者（MVP 固定「本地导入」） |
| content | string | 解码后的全文（一次性读入） |
| size | number | 文件字节数 |
| encoding | string | 探测到的编码 |
| cover | string | 封面色 key（用于渐变配色） |
| createdAt | number | 导入时间戳 |
| lastAt | number | 最近阅读时间戳（书架排序依据） |
| lastPage | number | 阅读进度（页下标） |

**`settings`（keyPath: `key`，单条记录 `key: 'reader'`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| fontSize | number | 默认 19 |
| lineHeight | number | 默认 1.9 |
| theme | string | `'day' | 'sepia' | 'night'`，默认 `'day'` |

> `totalPages` 由 `content.length` 派生，不单独落盘，避免冗余与不一致。

### 5.4 状态管理（`store/bookStore.ts`）

Zustand 单 store，字段与动作：

- **state**：`books: Book[]`、`currentId: string | null`、`currentPage: number`、`settings: ReaderSettings`；
- **actions**：`importFiles`、`deleteBook`、`openBook`、`gotoPage`（含进度落盘）、`setFontSize`、`setLineHeight`、`setTheme`、`loadAll`（启动时从 IndexedDB 读回）。

落盘策略：导入/删除立即写；翻页记录进度与改设置做**轻量防抖**（如 300ms）后写 `settings` / 对应书的 `lastPage`，避免连点造成写放大。

### 5.5 主题与样式

- 三种主题 = 三组 CSS 变量（`--rbg/--rfg/--rbar/--rborder/--rmuted`），直接沿用 demo 定义；
- 切换主题仅改根节点 class（`theme-day/sepia/night`），不重渲染 DOM；
- 阅读区字体用宋体系衬线栈，正文 `pre-wrap` 保留段落换行。

## 6. 关键流程

**导入**：`arrayBuffer → 编码探测 → decodeText → 写入 store → 落盘 books → 书架排序显示`。

**阅读**：`openBook(id) → 取 lastPage → pageAt(content, lastPage) → 渲染当前页`。

**记住进度**：`翻页/返回 → gotoPage 更新 currentPage → 防抖写 books.lastPage + lastAt`。

**恢复**：`启动 → loadAll 从 IndexedDB 读 books + settings → 书架按 lastAt 排序`。

## 7. 测试策略（遵循 AGENTS.md）

用 Vitest，优先覆盖纯逻辑模块：

- `encoding.test.ts`：UTF-8、GBK、UTF-16 LE/BE（含 BOM）、空文件等固定字节样本；
- `pagination.test.ts`：空文本、恰好整页、末页不满、页下标越界钳制等边界。

> 说明：Node 自带 full-ICU 的 `TextDecoder` 支持 `gb18030`，编码单测可直接在 Node 环境跑。组件层测试 MVP 阶段不强制，后续 UI 稳定后补。

## 8. 里程碑对应

| 里程碑 | 本方案落点 |
|---|---|
| M1：脚手架 + 导入 + 编码探测 | Vite/React/TS 脚手架；`lib/encoding.ts` + 单测；导入后正确显示文本 |
| M2：书架、删除、进度记忆 | `lib/db.ts` + `store/bookStore.ts`；书架列表/删除/排序；IndexedDB 进度 |
| M3：阅读器完善 + 大文件渲染 | `lib/pagination.ts`；字号/行距/主题；按需 slice 渲染 |

## 9. 风险与权衡

| 风险/权衡 | 影响 | 应对 |
|---|---|---|
| 固定字数分页页边界不准、大字号需页内滚动 | 体验略糙 | MVP 接受；后续可升级「测量式分页」或「连续滚动 + 虚拟渲染」 |
| 整本解码常驻内存 | 超大文件（数十 MB）内存偏高 | MVP 上限可控；后续可改 Blob + 分块解码 |
| GB18030 不覆盖 Big5 | 繁体文件乱码 | MVP 范围外；需要时引入 `jschardet` |
| IndexedDB 需处理 Safari 旧版兼容 | 少量用户存取异常 | 统一封装 `db.ts`，异常时 toast 提示并降级 |

## 10. 关键决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 前端框架 | React（放弃 Vue） | 核心难点框架无关，生态与后续扩展杠杆更大 |
| 分页 | 固定字数切片 | 最快、进度确定、O(1) 访问，MVP 首选 |
| 不预生成 pages 数组 | 存原文按需 slice | 避免上百万字时内存冗余 |
| 状态管理 | Zustand | 轻量，避免 Redux 过度设计 |
| 存储封装 | `idb` | 原生 IndexedDB 样板多，`idb` 更薄 |
| 编码探测 | 原生 `TextDecoder` 回退 | 确定性优于启发式，无需第三方库 |
| 后端 | 不需要 | 纯前端 + 本地存储满足 MVP |
